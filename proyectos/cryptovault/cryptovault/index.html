CryptoVault

Dashboard de monitoreo de posiciones DeFi en tiempo real. Añades una wallet de Ethereum o Solana y lee directamente de la blockchain sus posiciones de liquidez concentrada, balances y fees pendientes — sin backend propio.

MVP funcional
Tipo
Dashboard DeFi
Redes
Ethereum + Solana
Protocolos leídos
Uniswap V3, Orca, Raydium
Stack
HTML/CSS/JS puro

Arquitectura

Lectura on-chain sin backend

Todo corre en el navegador del usuario. No hay servidor propio: el HTML habla directo con nodos RPC públicos y con Helius para las posiciones de Solana.

Objetivos

Qué demuestra este proyecto

  • Consumir contratos inteligentes y programas on-chain sin depender de SDKs de terceros.
  • Codificar y decodificar manualmente llamadas ABI (Ethereum) y cuentas binarias Borsh (Solana).
  • Diseñar un sistema de control de acceso (propietario + lista de correos autorizados).
  • Detectar y resolver limitaciones reales de entorno (sandboxing, almacenamiento, CORS).
  • Construir una interfaz en tiempo real que sincroniza al conectarse.

Tecnologías

Componentes del proyecto

  • HTML / CSS / JavaScript vanilla
  • JSON-RPC Ethereum
  • JSON-RPC Solana
  • Helius API
  • CoinGecko API
  • Codificación ABI manual
  • Decodificación Borsh manual
  • localStorage / almacenamiento de artifact

Documentación

Guion técnico

  • Lectura de posiciones Uniswap V3 vía el contrato NonfungiblePositionManager (balanceOf, positions) y cálculo de cantidades a partir de liquidez y rango de ticks.
  • Localización de posiciones Orca Whirlpool y Raydium CLMM con getProgramAccounts + filtros memcmp, sin derivar direcciones PDA manualmente.
  • Verificación del formato binario de cada cuenta contra el código fuente público de cada protocolo antes de confiar en los offsets.
  • Sistema de acceso: primer correo introducido reclama la propiedad; el propietario añade o quita correos autorizados.
  • Sincronización automática al conectarse y refresco periódico mientras la sesión está activa.

La versión completa en Markdown se mantiene junto al proyecto en README.md.

Incidencia documentada

Problemas encontrados y solución

Síntoma: al guardar la lista de accesos aparecía el error "Storage set failed: Internal server error".

Comprobación: el sistema de almacenamiento usado (window.storage) solo existe dentro del entorno de artifacts de Claude — al publicar el proyecto en GitHub Pages, esa API deja de estar disponible.

Resolución: se añadió una detección automática de entorno: si window.storage no existe, la app usa localStorage del navegador como alternativa, sin que el usuario tenga que hacer nada.

Síntoma: las wallets no cargaban datos, con el error genérico "No se pudo leer esta wallet".

Comprobación: fallaba igual para Ethereum y Solana — señal de que no era un problema de una red concreta, sino del entorno de pruebas: la vista previa de artifacts en Claude.ai bloquea peticiones de red salientes hacia dominios externos por seguridad.

Resolución: se confirmó que la app funciona correctamente una vez desplegada fuera de ese sandbox (GitHub Pages), donde el navegador sí tiene acceso completo a internet.
